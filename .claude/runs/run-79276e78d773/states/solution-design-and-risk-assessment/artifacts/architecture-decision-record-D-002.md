# Architecture Decision Record: D-002

## Metadata

- ADR ID: D-002
- Title: Lesson bundle layout, guarded file naming, lesson-to-frontmatter mapping, and the lesson_record extension key
- Date: 2026-10-17
- Status: Proposed
- Owners: omn-architect, omn-tech-lead (Design Gate; omn-tech-lead decides under the Producer Exclusion Rule)
- Related Work Items: run-79276e78d773; technical-design.md; T-002, T-006, T-008

## Context

- Problem statement: Each lesson record must become one OKF concept document whose standard keys come only from record fields, while every record field stays readable and the read path returns identical records.
- Business and technical constraints: layout at memory/lessons with L-*.md, index.md, log.md (C-001); type, title, description, tags from record fields only (C-002); sources, generated, and Z instants (C-003); verified and status mapping (C-004); every field under an extension key with identical reload (C-005); no value can alter structure or form a path outside the bundle (C-017).
- Current architecture baseline: a lesson has 20 fields in LESSON_FIELDS order and lesson_id is L- plus 10 hex (F-004); render_section neutralises the description at cap 160 (F-006); evidence references are framework-relative with a fragment (F-011, F-026); OKF sources need resource, relative paths are allowed, and actors are producer/version or human:id (F-024).

## Decision

- Selected option: O-002.
- Decision statement: BUNDLE_REL is memory/lessons; each document is named lesson_id plus .md after lesson_id is checked against L- and exactly 10 lowercase hex, else store-unwritable. Frontmatter keys in order: type Lesson; title from neutralised kind, check or gate, and artifact type; description neutralised exactly as render_section does; tags from kind, artifact type, and phases; sources one entry per distinct evidence path before the fragment, resource prefixed by two parent steps; generated by knowledge-loop/1.0.0 at last_seen; verified one entry per approve history entry with a sanitised human actor; status draft, stable, deprecated for candidate, active, retired; stale_after per D-004; lesson_record carrying every LESSON_FIELDS value in order. The body is a title heading and a summary line and is never read back.
- Scope of impact: M-002, M-003, M-013.

## Alternatives Considered

1. O-001: same mapping implemented with all serialisation inside knowledge.py
- Benefits: one module fewer.
- Risks: the conformance check depends on the loop module.
- Why not selected: ranks second on criterion 4 (C-022).

2. O-003: bundle as an export of the retained JSON store
- Benefits: mapping can be lossy without harm.
- Risks: two stores of record.
- Why not selected: eliminated by C-011.

3. O-004: record as a fenced JSON block in the body
- Benefits: no frontmatter extension key.
- Risks: fields not readable under their own key.
- Why not selected: eliminated by C-005.

4. O-005: third-party YAML library
- Benefits: no custom serialiser.
- Risks: new dependency.
- Why not selected: eliminated by C-016.

5. O-006: incrementally appended log.md
- Benefits: none for the mapping.
- Risks: log depends on write history.
- Why not selected: eliminated by C-006, C-008.

## Consequences

- Positive outcomes expected: standard OKF keys for third parties; lossless reload through lesson_record; dispatch text unchanged because the description uses the render_section rule.
- Tradeoffs accepted: every field appears twice in substance (standard key and lesson_record); the document format version 1.0.0 is a new identifier to maintain.
- Risks introduced: R-001, R-008, R-016.

## Validation Plan

- Metrics to monitor: field checks of every document against its record; resource sets against evidence paths.
- Verification checkpoints: contracts accepted (P-001); write and read exist (P-006); AC-002 to AC-008 and AC-023 on the migrated bundle, hostile fixtures, and the identifier guard fixture (P-013).
- Rollback or reversal conditions: if Q-001 rules that resources carry bare framework-relative paths, revise the sources value form under a new record before P-006.
