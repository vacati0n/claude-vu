## Implementation Summary

- Change intent: the condition that blocked `fix-bug/triage-and-impact` is now detected by an executable check instead of by a run reaching the phase; the framework no longer documents the two readers of the Phase Model Output Artifact column as agreeing when they agree on only one of the three shapes a cell can take; the defect-repair workflow's prose no longer contradicts its own corrected table; and the two verifier checks this increment regressed, `V4` of the validator coverage proof and `M6` of the multi-phase proof, both pass again on their own terms rather than by being weakened.
- Approach taken: the operator's earlier correction was measured rather than assumed, by resolving the phase end to end and re-deriving every active workflow's dependency graph against a baseline taken first; one incompleteness was found and corrected, a comment stating the phase declares no slice sitting directly above the slice entry the same correction had added. The detection gap was closed by asking the coverage proof's question the other way round: `V1` asks whether every artifact a Phase Model names has a validator, which a row naming no artifact answers by contributing nothing, so `V5` asks of every row whether the artifact the runtime derives from it has a registered validator, and `V6` tests the two readers against each other over cells naming zero, one, and two artifacts. Two regressions this increment caused were then repaired at their cause: the bug-analysis mutation anchor became a derivation from the instance under test, matching the four derivations the same file already carried for the same reason, and `M6` was moved onto the point-in-time evidence rule by replaying the run's append-only transition log to the baseline the run recorded, reusing the reconstruction helper the self-hosting proof already applies. No source file was written in this attempt; all four were written in attempt 1 and their digests are unchanged.
- Design reference: the accepted root-cause analysis at `runs/run-27e36c138498/states/root-cause-analysis/artifacts/bug-analysis.md`, whose root cause is that no rule governs the Output Artifact column while three consumers read it under three unstated requirements, and whose `Why detection failed earlier` names evidence `E-010`, the coverage proof never examining a prose-only row, and evidence `E-019`, the runtime's own source asserting that the two artifact readers agree; evidence `E-014` names the workflow narrative contradicting its own table. The two regression repairs are governed by decision `GD-001` in `config/self-hosting-profile.md`, the point-in-time evidence rule, and by the derivation pattern the validator coverage proof already documents for four other artifact types.
- Out of scope: giving the five remaining prose-cell rows an artifact type, template, and registered validator, which the analysis routes to the architect and which `O-001` of `proposals/framework-change-proposal-FC-004.md` tracks as a separate increment; enforcing a column contract at authoring time, which cannot land before that decision; re-evaluating work items already recorded blocked in earlier runs; and repairing the verifier finding recorded as `Q-002`, which this increment surfaced but was directed not to fix here. Leaving these is safe because none is needed to remove the reported symptom or to detect its recurrence: the five rows stay exactly as they are, `V5` records them as outstanding by name rather than passing over them silently, and a newly authored row of the same shape now fails a check instead of blocking a run. Two documents outside the stated scope still use this phase as their example of a blocked phase; they are recorded as `R-003` rather than edited.
