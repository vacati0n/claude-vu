## Implementation Summary

- Change intent: a non-editable wheel install of the CLI now carries a complete, resolvable copy of the framework payload inside the `omn_agent` package, so a fresh environment can run `init`, `install`, and `validate` with no `--source` flag, while every existing resolution mode -- explicit source first, then a checkout-adjacent framework tree -- behaves exactly as before, including every failure mode.
- Approach taken: the design's selected option O-001 as accepted -- a bundled payload data subtree inside the package (`omn_agent/_bundled_payload`, an exact committed mirror of the framework payload directory at the repository root: all ten managed directories plus both seed directories, filtered by the installer's own exclusion-pattern constant), declared as package data in the packaging configuration through two recursive glob patterns (the second covering dot-named files the first cannot match); `find_source` gains exactly one appended last-resort candidate resolved from the installed package location, validated by the existing framework-tree check unchanged, with the typed failure and its hint retained verbatim; the mirror is refreshed by a one-line sync command carried in the new test module and locked by parity tests that fail the suite on any file-set or content drift.
- Design reference: decision records D-001 and D-002 (with inline decisions D-003 and D-004), impacted modules M-001, M-002, M-003, and M-008 delivered; M-004 deferred under deviation `V-001`; M-005, M-006, and M-007 verified untouched; sequencing constraints P-001 through P-004 and the executable portion of P-007, of technical design CKA-02-technical-design.
- Out of scope: gate-decision recording, gate-matrix semantics, producer exclusion, approval-requirement enforcement, and every human-block path (the design's additive-only constraint, confirmed by a forbidden-symbol search across every changed file); any precedence change for existing users; the dependent continuous-integration ticket CKA-03; the installer, validator, and target-resolution modules, which the design records as no-change -- the installer consumes `find_source` unchanged and its source-equals-target guard already covers the bundled candidate, since the bundle lives under the installed package and never under a target framework directory; and user documentation, which the design sequences after verified behaviour (P-009). Leaving each is safe because the change is purely additive at the end of the candidate list in one branch, and no untouched module's inputs changed shape.

- Module boundaries preserved: the change stays inside the modules the design names -- the packaging configuration, the source-discovery module, a new data-only subtree inside the package, and the test suite. - Data or migration impact: none -- no data store, manifest format, bootstrap descriptor schema, or installed-target layout changed; installed targets are governed by the install manifest and are unaffected, and withdrawing the package-data declaration and the appended candidate would restore the prior shape without touching any installed target.
