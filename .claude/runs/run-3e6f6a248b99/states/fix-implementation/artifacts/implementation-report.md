## Implementation Summary

- Change intent: a gate rejection is no longer a dead end. After a listed, non-producing gate owner records a rejection, the new `rollback` command authorises the rollback the recovery contract already classifies: every completed phase from the named target through the phase the gate closes is superseded (returned to pending as a new attempt under its existing idempotency key, its committed artifact left byte-identical, its prior completion moved unmodified into an append-only supersessions list), the rejected gate is re-armed on the same work item with the rejection kept in an append-only decision history, the successor's stale block and any undecided gate over the superseded phase return to pending, the re-dispatch carries the rejection as prior_rejection and writes to an attempt-scoped artifact path, the re-armed gate is decided again only by a human, every rejection envelope names the executable `rollback` command as its clearing action, and the state engine admits exactly two exits from a terminal status, one of them engine-checked against a supersession record.
- Approach taken: two transition-table entries in the state engine with an engine-side record check on the superseded pair and an AUTHORISED_EXITS table the verifiers read; a `rollback` subcommand in the runtime sharing the factored listed-owner and Producer Exclusion checks with `gate`, validating the target as the closed phase or a completed hard ancestor, refusing when any phase in range has spent its charged attempts, snapshotting per-attempt files under states/<phase>/attempts/<n>/, and re-arming the gate; the dispatch path split into a canonical path (payload digest) and a declared attempt-scoped path (envelope, permitted writes, state ledger) with prior_rejection beside prior_validation and a rework-pass section in the dispatch prompt; the scheduler's waiting branch moving a guard-raised block whose guards fall to wait back to pending for both work types; class-aware clearing actions with the G4 verdict carrying the gate name as a structured field, the gate-rejection option list dropping the exception option, and the gate item labelled gate-rejection at rejection; the auto-approval path holding any gate with a decision history; status views, completion package, final report and run ledger surfacing supersessions and decision history; verify_multi_phase M4/M12/M13 extended; verify_recovery Run D plus an admissibility check over every open envelope; the fix-comments consumer issuing reject then rollback with the same role and the task's fix phase as target, with both consumer test stubs replaced by the real post-rollback status shape; contract text updated and the handbook re-rendered; the bundled payload mirror re-synced.
- Design reference: root-cause analysis Fix Strategy conditions (1) two transitions with engine check, (2) rollback command and preconditions, (3) attempt-scoped immutability and the key-versus-path split, (4) same-item gate re-arm with decision history and the gate-rejection class, (5) scheduler wait correction for both work types, (6) human re-decision after rollback, (7) class-aware clearing actions and option list, (8) no migration, (9) contract text and consumer sequence, (10) run-status projection left out of scope; architect decision memo sections Decision (1) to (6), Transitions added, Invariants preserved, Verification the fix must add; architect confirmation of the two open readings.
- Out of scope: the run-status projection and aggregator defect (run_completed fires while a final gate stands rejected; a supersession after run_completed is now possible), recorded by the memo as out of scope and carried here as a residual risk; the operator action on the stranded run run-4c51600606df, which by instruction is executed by the operator after the Fix Gate and is proven here only on a harness run of the same shape; the `remediate` action and the workflow-contract-violation rollback verdict, which remain decided rather than executed as the runtime README now states; the retry-class clearing action's optional reclaim suffix, whose `release` on a retrying item is a pre-existing no-op and not a gate-rejection concern; `omn_agent/update.py`, which never rejects a gate (a changed input archives the run) and so shares only the status helpers, left unchanged.
