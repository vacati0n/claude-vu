## Implementation Summary

- Change intent: check V4 of the validator coverage verifier no longer depends on which run sorts last or on identifier rendering: the orchestration mutation finds its Phase Progression row by an identifier cell with or without backticks, and each type's instance is the first candidate on which the declared mutation resolves, with every skipped candidate reported and a loud V4 failure naming every candidate when none applies; V3 validates exactly the instance V4 mutates; the console mutation line prints the observed outcome. On unchanged run evidence the verifier reports 6/6 COVERED, with the run-d8937789961e closure record selected, caught by O4 alone, and no candidate skipped.
- Approach taken: in runtime/verify_validators.py, `award_itself_its_own_gate` matches column one against a new `PHASE_ID_CELL` pattern (optional backticks, the rule of the contract engine's defined_ids) instead of requiring a backticked identifier anywhere on the line; a new `candidate_instances` beside committed_instances lists committed instances last to first in the existing lexical run-identifier order, then governance records last to first, then the fixture; `conforming_instance` walks that list and returns `(instance, source, envelope, skipped)`, skipping a candidate only when `resolve_mutation` finds no anchor, never consulting validator acceptance or the mutation verdict; a small `instance_label` gives the printed path; the V3/V4 loop in main unpacks the four values, records each skip in the V4 detail (passing or failing), the console, and the JSON summary, and when no candidate applies fails V4 naming each candidate while V3 still validates the first candidate tried; a new `mutation_outcome` renders the console line from the finding. Rungs of the ladder: the new functions are rung 7 (the analysis names the candidate helper; no existing function lists candidates, labels a path, or renders an outcome); no file and no dependency was added. The first repair's recommend_an_unevaluated_option, resolve_mutation and mutation_verdict are unchanged. The test module gained ten tests; the bundled mirror was regenerated by its sync command.
- Design reference: root-cause analysis Fix Strategy (rendering-neutral row locator; fixed candidate order taking the first on which the mutation resolves; no filtering on validator acceptance; skipped candidates always reported; loud failure naming every candidate; docstring stops calling the order newest; console line reports the observed outcome; no validator, template, fixture or run evidence change) and its Validation Plan (reproduction expecting 6/6, the listed regression tests, full suite).
- Out of scope: every validator, template, fixture and committed run artifact; the orchestration contract's identifier rendering, routed by the analysis to architect; the F7 rejection of the change proposal from inside the framework directory, a separate defect the analysis routes to omn-tech-lead; candidate order by creation time, rejected by the analysis; the count-based derivations, which the new fallback now covers; observing the main checkout and hosted CI, routed to omn-qa.
