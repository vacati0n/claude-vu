## Technical Changes and Compatibility

- API or contract changes: three. (a) `docs/USER-GUIDE.md` gains an authoring grammar that contributors write against: a trailing brace attribute on a heading carrying its anchor identifier, a blockquote whose bolded lead-in run is its callout tag (with a variant class on its own line where a list needs one), and a fenced block whose info string names a chain diagram; the 21 anchors, 14 callout tags, 14 internal links and one list variant are now authored in the source (technical design D-001 to D-005 and section 6; implementation report C-003). (b) `docs/user-guide.html` loses its hand-editing contract: it is a build output, rewritten once wholesale as renderer output under the Design Gate's Q-005 ruling, and every regeneration reproduces it byte for byte from the source (technical design D-007; implementation report C-005). (c) `tools/render_user_guide.py` is a new command-line surface with a default render mode, `--check` and `--root DIR`, and `escape_attribute` is a new module-level function beside `escape` (implementation report, Public interface changes). The verification workflow's six job identifiers and four stable check names are unchanged, so no branch-protection edit is required and none is proposed (technical design D-008; review package, Architecture rules).
- Database or migration impact: no data model, schema, migration or backfill. The one migration is of the published page's own bytes, once and in one direction, from hand-authored to generated; it is reversible by reverting the change set, which returns the page to its pre-change committed bytes (technical design section 6 and Rollout and Rollback; implementation report, Data or migration impact). The pre-change page is frozen byte-identical to the committed file as `tests/fixtures/user-guide-pre-change.html` and the page as regenerated when the reconciliation closed as `tests/fixtures/user-guide-reconciled.html` (implementation report C-001 and C-007; Review Gate rationale).
- Configuration changes: a new `.gitattributes` at the repository root pins `docs/USER-GUIDE.md` and `docs/user-guide.html` with `-text`, so the committed bytes reach disk verbatim on both CI legs and under `core.autocrlf=true` (implementation report C-008; Design Gate condition 2; test T-009). One step is added inside the existing `tests` job of `.github/workflows/verify.yml` (implementation report C-010). No new dependency is introduced, the tool being standard library only (technical design C-003), and no runtime, gate-decision or approval surface changed (scope exclusion X-002; review package, Architecture rules).
- Backward compatibility notes: for a contributor who has been editing `docs/user-guide.html` directly this is a breaking change. An edit made there is discarded by the next regeneration, and a commit carrying it without a matching source change fails the drift check; the required action is to edit `docs/USER-GUIDE.md` and run `python tools/render_user_guide.py`, which the banner at the top of the page, README.md and the handbook's own CI subsection now state (technical design D-003 impact, R-010 and the section 6 notes for the published handbook; Verification Gate A-002 and A-009). For a contributor who writes plain Markdown in the source the grammar is additive: a heading without an attribute still renders, taking a derived slug, and a paragraph that is not a blockquote still renders as a paragraph, so an unadorned document remains valid; only a heading that must expose a stable identifier needs the attribute, and the reconciliation landed all 21 at once (technical design section 6, notes for the source handbook). Two forms the renderer accepted silently at attempt 1 are now render failures naming the source line: a heading no heading form matches, and a quote or an out-of-alphabet character in an identifier or class name (review package F-006 and F-008). Readers who link into the page by anchor are unaffected, because all 21 identifiers and the internal link graph closed over them are preserved exactly (Verification Gate A-008; technical design Appendix B). The existing tests that read the page, `tests/test_ci_workflow.py` and `tests/test_omn_agent.py`, keep passing because every string they assert was carried as a non-droppable merge (Planning Gate ruling on Q-003; tests T-012 and T-013).
