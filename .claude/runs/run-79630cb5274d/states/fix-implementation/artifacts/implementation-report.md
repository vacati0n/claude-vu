## Implementation Summary

- Change intent: the accepted-input menu of `omn-dev-1-implement` now declares the identifier its refactor predecessor actually publishes, so the artifact the `refactor` Phase Model routes across the phase 2 to phase 3 edge survives input narrowing and satisfies the menu rule, and guard G5-INPUT no longer blocks `refactor-implementation`. The identifier that no agent anywhere declares as an output is withdrawn from that menu in the same edit, and the five surfaces that describe this agent's inputs now state the same set the menu implements.
- Approach taken: declaration-only. No runtime module was modified. The guard, the narrowing function and the contract resolver are unchanged; the repair comes entirely from the declarations they read. The manifest menu was widened additively, keeping `technical-design` and `bug-analysis` with their present meaning and phases, and `test-baseline-record` was removed. The manifest's minimum-satisfaction prose, the required-input list in the agent contract, the phase-ownership table in the execution lifecycle, the registry record's data dependencies and the report template's enumeration comment were each brought into agreement with that menu. The agent's own semantic-versioning block makes a backward-compatible input addition a minor step, so the manifest version and its registry record both move 1.0.0 to 1.1.0 while `contractVersion` stays at 1.0.0, because that field names the shared agent-specification revision and this change does not touch that specification. One contract-level test module was added. The committed mirror of the framework payload was refreshed by the repository's own sync command, because the suite fails on drift between the two trees.
- Design reference: the finalized root-cause analysis at `runs/run-79630cb5274d/states/root-cause-analysis/artifacts/bug-analysis.md`, its Fix Strategy and its Validation Plan.
- Out of scope: the thirteen other declared data edges that share this defect's cause; the analysis routes them as their own work and this change does not reach them. The two framework-wide prevention checks the analysis names — a per-edge producing-identifier check and an orphan-identifier check — which the analysis deferred because both fail or misreport against the repository as it stands. The extension of the per-phase dispatchability verdict to report the input-contract guard, deferred with them. The Completion Rule's phase-accounting clause, which the analysis establishes as an independent defect with an independent reach. A per-phase narrowing of an agent's accepted menu, which is a runtime and schema design decision the analysis routes to architecture. Executing the unblocked refactor phase: the phase was proven dispatchable, and dispatching or completing it was excluded by the invocation that produced this change.
