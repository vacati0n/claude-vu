## Root Cause Analysis

- Root cause statement: The consuming agents' accepted-input contracts, which each agent enforces again in its own first reasoning stage, were declared without reference to the Phase Model edges that feed them, so the context agent names the framing output by two identifiers nothing produces, tech-lead's recommendation phases are routed only an artifact its contract does not name, documentation's contract defines no input for the findings publication it owns, and the profile names entry types the entry agent does not accept, with no check composing a Phase Model edge with the producer's identifier and the consumer's contract.
- Why detection failed earlier: Registry coverage check C6 evaluates only the capability and context guards and never G5-INPUT; verify_manifests reads only write scopes and example pointers; self-hosting check S2 resolves each row's command, workflow, and entry phase but never tests its Required Inputs against the entry agent (`E-033`). The per-edge and producer-existence checks were deliberately deferred by the earlier refactor repair because they failed on arrival, not because the design rejected them (`E-014`, `E-017`). No check compares a host registration's stated version with its manifest, which is how the earlier repair's version drift survived (`E-020`).

## Fix Strategy

- Proposed fix: Make each in-scope consumer's contract state the artifact its Phase Model edge delivers, in the place that consumer's own contract already points, and make the two in-scope profile rows name the entry type the entry agent defines for these runs; the guard code stays unchanged and keeps rejecting any type the consumer does not declare (`E-030`, `E-032`). Entry inputs: decision-support and external-research name problem-statement (`E-012`). Hand-offs: the context agent accepts requirement-framing in place of framed-objective and research-brief, which denote that same framing output and were never supplied (`E-022`); the recommendation and recommendation-draft rows' Input column also names investigation-report.md, the evidence base tech-lead's unchanged contract already accepts, so tech-lead gains no input and keeps its version (`E-023`, `E-031`); documentation accepts technical-recommendation for the findings basis of its two publication phases, and its lifecycle table names technical-recommendation.md for them (`E-024`). Every surface that states a changed contract changes with it, as in the earlier repair: minimum-satisfaction and identity text, the context agent's sourceInputs vocabulary and its report template comment, registry data dependencies, version 1.1.0 for both agents in manifest, registry, and host registration with contractVersion held, the investigate and research workflow versions under their additive rule, and the bundled payload synced by its own command (`E-018`, `E-020`, `E-036`). No runtime module or runtime version changes. The committed stalled run is not re-evaluated as part of the fix; its disposition stays with the gate owner (`E-034`).
- Alternative options: (A for all three consumers) also add technical-recommendation to tech-lead's menu: tech-lead would accept its own output as an evidence base in all six of its phases, needing a third version move and resetting Merge and Readiness Gate precedent (`E-019`, `E-023`). (B) A runtime alias from an output identifier to an accepted type works only for the context agent; tech-lead and documentation accept nothing corresponding, so an alias would mislabel the artifact (`E-013`, `E-024`). (C) Letting an Input-column edge artifact satisfy G5-INPUT passes 28 of 29 edges with no version change, but it dispatches agents whose own first stage still refuses the input, moving the block into a charged attempt; it makes G5 equal to the predecessor guard at every such edge, rests on fuzzy term matching, and silently changes 6 out-of-scope hand-offs, so it is weaker than the status quo (`E-021`, `E-029`). (D) Per-phase menus in manifests restate the Phase Model's per-phase facts in a second place, a schema and runtime change that recreates the independent-declaration condition; it stays architect's structural question (`E-017`, `E-019`). (E) Profile-only repair rescues the context agent with an extra raw question but needs mislabelled types for tech-lead and documentation (`E-009`, `E-013`).
